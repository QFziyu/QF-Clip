# 双路合成（1.3.0）

当前程序为 1.4.0；旧版本包已按用户要求清理，只保留最新 GPU/CPU 入口。下文双路工作流仍适用。

新增主播多素材顺序拼接、开球/进球等画面事件辅助对轴，操作与原理见 [1.4 使用说明](VISUAL_SYNC_SEQUENCE.md)。默认自动对轴仍是共同声音指纹，语音语义及图片模型均为可选辅助，不能保证事件或逐帧同步。

## 比赛声音处理（1.3.1）

「比赛录像静音」会完全去掉比赛录音中的解说与现场声；「保留主播声音」独立控制主播音轨。两个都关闭时导出完整的静音视频。只保留主播是默认效果。先保存设置再预览或导出；自动对轴继续使用原始声音。

不静音时，可选「AI 去解说人声，尽量保留现场声」。这是本地 Demucs 可选接入，本机**尚未完成依赖和模型安装，也未验证真人分离效果**。普通静音不依赖模型。需要时运行 `python -m pip install -r requirements-vocals.txt --cache-dir ./cache/pip-vocals`，安装匹配的 PyTorch/torchaudio；首次模型调用还需下载预训练权重。GPU 分离需要 CUDA 版 PyTorch，与 faster-whisper 的 GPU 依赖独立。自动设备不可用时回退 CPU，显式指定 GPU 不可用时提示改用 CPU。实际效果可能有解说残留或现场欢呼损失，先试听短预览。模型失败会报错并保留已完成块，不会偷偷用原解说音轨替代。

新增设置 `match_audio_mode` 为 `original` / `mute` / `remove_vocals`，`vocal_device` 为 `auto` / `cpu` / `cuda`；旧设置自动补默认值。AI 分离按源时间固定 30 秒块加上下文处理，缓存已完成结果并保持原时间轴。此处理仅针对比赛音轨，主播录音中的串音不在此范围内。

## 网页操作

1. 打开主界面，左侧选择「双路合成」，展开「新建双路合成」。点击「选择比赛录像」和「选择主播录像」，在弹出的系统文件窗口中各选一条录像，路径会自动填好，再点击「创建合成项目」。取消窗口会保留之前的选择。仍可直接粘贴本地路径；省略后缀时，仅在同名视频唯一的情况下自动补全。列表展示名称会隐藏后缀，磁盘文件不改名。音轨从 0 开始。
2. 点击「开始自动对轴」。后台扫描两路完整音轨的声音指纹，支持录制开场相差数十分钟。网页关闭也不影响任务；在「任务队列」查看日志，完成后回来点击刷新。
3. 有建议偏移时点击「采用建议偏移」。默认完整缩放主播画面到输出宽度的 25%，放在左下角。可选宽度、四个角落、声音来源和音量。
4. 可选「人脸跟踪 · 16:9 裁剪」：OpenCV 每秒抽样检测，平滑移动裁剪窗。多人可能选错人；漏检沿用最近位置，整段无可靠人脸或缺少依赖时保持完整画面，并在输出记录中提示。它不是人物身份识别或逐帧锁定。本机已安装所需依赖。
5. 保存设置，生成最多 20 秒短预览。分别在前段、中段、后段预览，核对嘴型或同一事件位置。必要时输入两条录像中同一事件的秒数，勾选使用事件位置校准后保存；也能直接修改偏移，小数可精调。
6. 确认后勾选「已核对同步位置」并保存，选择导出起止，提交正式导出。默认范围是两路共同覆盖的全部时间。输出文件名使用保存的标题，路径展示在网页；可在「项目」中导入该合成文件继续 AI 切片和字幕编辑。

先保存设置，再提交渲染。任务保存提交时的设置快照；期间修改设置不会更改已排队任务。改设置会生成新目录，保留旧输出。

## 时间轴和声音

`主播录像时间 = 比赛录像时间 + 偏移秒数`。各录像时间均从其第一帧开始，已处理容器起始 PTS、音视频流偏移；不是比赛记分牌分钟。例如同一事件比赛录像 120 秒、主播录像 360 秒，偏移是 +240 秒。

公共范围为 `[max(0, -偏移), min(比赛时长, 主播时长 - 偏移)]`，没有共同范围时会报错。原文件保留；输出 MP4、metadata.json、同名 timeline.json，记录源文件签名、两路原时间、输出时间和布局。编码器沿用配置，支持 NVENC，失败回退 libx264；默认横屏输出，主画面等比缩放并补边，避免裁掉赛事内容。

声音默认仅用主播；也可仅比赛或混音，两路分别调音量。所选声音源没有音轨会提示修改；无声比赛画面仍可与有声主播合成，但无法声音自动对轴。输出视频继承目录访问权限。

25% 指主播窗口**宽度**，不是屏幕面积。默认小窗容器为 16:9，完整缩放模式保留所有画面并补边；人脸模式才裁剪为 16:9。

## 自动对轴的边界

共同声音最可靠，例如赛事原声、同一解说、特征明显的哨音及现场反应。先全长粗匹配，再在三个分散位置做约 0.05 秒的细匹配，返回候选、局部证据、可信度和偏移分散程度。重复音乐可能存在多个同样合理的位置，会标低可信度，不能直接认定同步。

两路完全不同解说、主播只录了人声时，不能承诺自动精确对齐。可勾选语音与 LLM 事件辅助：复用相同源及音轨的已有转录，或按现有 Whisper 配置分块转录两路；向 LLM 发送每路最多 50 条、每条最多 180 字的事件摘录，模型只能关联已有摘录 ID。至少三个时间差接近且跨越一分钟的事件锚点才给出偏移建议，始终标为待核对。解说反应延迟、复盘描述会影响结果。预算和重试沿用 OpenAI 配置，独立账本在该合成缓存中；默认不开启，不会因为普通声音匹配调用付费 API。ASR/API 出错保留声音结果和已完成转录，可修复后重试。

本版每次合成使用一个固定偏移，不自动变速纠正时钟漂移或跳过插播。两路中途不同步时，请拆成连续的几段，分别校准和创建输出；同一合成项目可多次用不同偏移/起止导出，旧成品保留。

## CLI

```powershell
python main.py compose-create "D:/videos/比赛.mp4" "D:/videos/主播.mp4"
python main.py composites
python main.py compose-sync --composite ID --background
# 可选转录/LLM 事件辅助，允许 GPU 失败后 CPU 回退
python main.py compose-sync --composite ID --semantic --allow-cpu --background
python main.py compose --composite ID --options options.json --preview --preview-start 120 --background
python main.py compose --composite ID --options options.json --segments ranges.json --background
python main.py jobs --job JOB_ID
```

`options.json` 可只填写需要覆盖的字段，其他字段回到默认值：

```json
{"offset_seconds":240,"sync_confirmed":true,"layout":"fit","width_ratio":0.25,"position":"bottom_left","audio":"commentator","title":"比赛与主播合成"}
```

`ranges.json` 是比赛录像时间的有序、不重叠区间数组，最多 200 段。省略则导出全部公共范围。网页提供单一区间，CLI 支持多段拼接。

```json
[{"start":120,"end":180},{"start":600,"end":660}]
```

## 依赖和恢复

```powershell
python -m pip install -r requirements-face.txt
python scripts/composite_demo.py
python scripts/run_tests.py
```

人脸依赖为可选项，无需下载额外人脸模型；完整缩放、声音指纹均不依赖 OpenCV。新机器需要额外安装此依赖才能追踪人脸。测试依赖 numpy，已在主依赖中。

双路项目、同步结果、设置审计、输出历史保存在 SQLite 的 composites/composite_audit；声音特征、语义结果及转录按签名缓存在 cache/composites。源文件被移动、覆盖或改写会要求重新创建项目，避免复用旧对轴。合成失败不改写源文件或已有成品；任务队列可重试。原有切片审批、字幕及导出记录不迁移。

演示脚本生成合法测试图和合成声音，使用独立数据库，通过真实 CLI 和分离进程队列导出 12 秒样片，验证文件可完整解码以及输出声音的时间映射；不调用真实 API，不代表已完成真实两路赛事实验。

系统文件选择窗口在运行本程序的电脑上打开，适用于本机桌面使用。直接读取原文件，不通过浏览器上传或另存大视频。窗口无法打开时会提示，并保留路径输入作为备用。
