# 内容模式与长视频剪辑开发计划

日期：2026-10-17。状态：需求选择已收集，供审阅的开发计划，尚未实施。

## 一、已确认的用户意图

内容判断标准与成品形式分别选择，可以组合使用。

| 维度 | 选项 | 用途 |
| --- | --- | --- |
| 内容标准 | 比赛 | 以现有高召回比赛剪辑规则为基础，关注比赛进程、反应、争议与关键事件 |
| 内容标准 | 足球对话 | 足球节目、聊天、新闻讨论，关注完整话题、观点、争论、球员评价及趣味交流 |
| 内容标准 | 自定义 | 用户编辑提示词、关注主题、必保留内容和排除内容，并保存为个人模板 |
| 成品形式 | 多条短片 | 自动捕捉要点，产出多条独立候选，保留现有高召回流程 |
| 成品形式 | 连续长段 | 找出一两段完整连续内容，保留中间对话或比赛过程 |
| 成品形式 | 多段集锦 | 从原素材选择多个时间段，按时间顺序拼成一两条较长成品 |

用户选择同时支持两种长片形式。关键事件输入采用比赛分钟，例如上半场第 35 分钟、下半场第 61 分钟，需映射到原录像时间。

各组合支持设置目标成品数量、单条目标时长、允许的最短与最长时长。目标是规划偏好；必剪事件或完整语句与硬性时长冲突时需报告，不能静默删除必剪事件、虚构片段或凑数量。

## 二、用户操作流程

1. 导入录像，选择音轨、内容标准、成品形式。
2. 设置目标条数与每条时长范围；使用预设时可以直接开始，详细参数按需展开。
3. 可选编辑本项目提示词或另存个人模板。保留合法时间戳、来源依据等程序校验，提示词不能覆盖这些约束。
4. 比赛模式可填写比赛时间校准点及必剪事件清单。
5. 系统复用转录，生成短片候选或长片草稿、关键事件覆盖表。
6. 审核预览，修改标题、范围和字幕；集锦还可调整各段边界、保留或移除非必剪承接段。
7. 仅导出通过的草稿，继续使用已有字幕样式、片头、横竖屏和 GPU/CPU 导出设置。

## 三、必剪事件定位

### 1. 比赛时间与录像时间校准

提供轻量的校准表：比赛阶段、比赛时间、对应录像时间。通常上、下半场分别提供一个可信校准点，例如“下半场 45:00 = 录像 00:12:40”。系统可从转录建议位置，但需要用户确认；第一版不依赖比分牌 OCR。

支持常规比赛分钟和补时写法，例如 `35:20`、`45+2:10`、`90+4:00`，并区分上下半场。加时赛通过显式比赛阶段处理。素材从比赛中途开始也可校准。存在删节、暂停录制或拼接时，增加对应连续区间的校准点，不能假设整场只有一个固定偏移。

### 2. 必剪事件清单

输入包括比赛阶段、分钟、事件类型、备注和重要性，例如：

| 比赛阶段 | 比赛时间 | 事件 | 要求 |
| --- | --- | --- | --- |
| 上半场 | 35:00 | 进球 | 必须保留，带进攻铺垫及反应 |
| 下半场 | 61:00 | 越位 | 必须保留判罚及必要说明 |
| 下半场 | 78:00 | 红牌 | 必须保留事件及后续反应 |

分钟通常为近似位置，先映射搜索区间，再结合附近转录、声音线索和用户预览调整边界。用户明确指定的区间可以在缺少语音时保留，来源标记为人工事件，不能沿用“必须有转录引用”的语义候选规则把它删掉。

### 3. 覆盖检查

每条事件记录输入、映射区间、候选来源、定位状态、实际采用区间和所属成品。状态至少区分已定位待确认、已确认采用、定位不确定、不在当前素材、与时长约束冲突。

LLM 只能说明转录中的反应，不能仅凭文字确认画面发生了进球或红牌。人工给出的事件来源与模型推断必须区分。未解决的必剪事件不允许被静默丢弃并标记“全部完成”；草稿可保存，正式导出需用户解决或明确调整该事件要求。

## 四、长视频处理方式

现有程序已按约 5 分钟转录、约 6 分钟分窗口选片，并保存检查点。输入文件长度与输出片段长度是不同参数。不能把两三小时素材无法稳定处理直接归因于时长限制；应分别验证模型显存、请求超时、预算、缓存及渲染阶段。

长片规划增加一层全局组织：

`分块转录缓存 → 带原文引用的话题/事件索引 → 全局选择与分组 → 边界复核 → 草稿预览 → 审核 → 成品`

- 连续长段：根据话题边界跨多个分析窗扩展，形成完整连续区间；目标长度不受当前 240 秒短片上限限制。
- 多段集锦：以已定位的必剪事件为骨架，按时间顺序补充必要进程和承接；删除重复，不补虚构内容。第一版使用直接切换，不加自动生成旁白或复杂转场。
- 不把整场原始转录一次塞进 LLM。窗口索引及分层汇总均有长度限制、缓存、重试和预算，保留原片区间与证据链。
- 用户可以先处理一小时文件，输出一两条长片；同时保留对完整两三小时文件的分块处理能力，使用合成材料做长时间轴与中断恢复测试，再按可用真实素材实验。
- “转录块大小”“LLM 分析窗口”归入高级设置；“成品时长”是独立的用户参数，不使用 batch size 指代成品长度。

## 五、代码改造边界

| 部分 | 计划 |
| --- | --- |
| 配置与提示词 | 新增比赛、对话、自定义模板；统一保存内容标准、成品形式、数量、长度及事件要求 |
| 转录 | 复用 `core/transcriber.py`；更换剪辑标准或成品形式不重新识别语音 |
| 分窗分析 | 扩展 `core/clip_selector.py`，增加可追溯的话题/事件索引与全局规划缓存 |
| 时间轴 | 扩展 `core/timeline.py`，加入比赛时间校准、必剪事件约束和长段边界复核 |
| 长片草稿 | 新增草稿结构：一条连续长片含一个源区间；一条集锦含有序多个源区间，各段保留来源映射 |
| 渲染与字幕 | 复用 `core/clip_renderer.py` 的编码流程，新增多段拼接及分段字幕重映射，再叠加已有片头偏移 |
| 存储与队列 | 使用可迁移的新表或字段保存模板、草稿、事件、覆盖状态及任务参数快照，不覆盖旧审批历史 |
| UI 与 CLI | 添加相同的内容标准和成品形式参数，集锦审核展示完整预览及分段清单 |

现有语义/声音/混合三种选片手段作为内部分析手段保留，与新内容标准区分命名。首版不同时引入更多用户可见“模式”开关。

同一录像允许保存多套剪辑方案，方案分别审批。缓存键包含内容标准、提示词内容、成品形式、时长规则和事件清单等；转录缓存独立复用，避免换规则误用旧决策或替换已审核方案。

## 六、分阶段实施

1. **内容标准与输出参数**：完成模板、提示词编辑保存、数量与长度设置、CLI/UI 与队列参数；保留原短片行为作为默认，验证旧数据兼容。
2. **连续长段**：增加话题索引与跨窗规划，支持一两段连续长片及独立审批，验证多窗口字幕与中断恢复。
3. **比赛事件与多段集锦**：完成时间校准、补时解析、必剪事件覆盖、多个源区间组织、字幕重映射及完整预览。
4. **回归与版本交付**：完成合成端到端测试、长时间轴和失败恢复测试；有可用授权素材时再做实际实验，写明测试范围，保留升级前可运行版本及数据库备份。

## 七、验收条件

- 比赛、对话、自定义标准可分别与三种成品形式组合，参数重开后不丢失。
- 同一转录可生成多套方案，旧方案审批及已导出文件保持原样。
- 短片不为达到条数凑重复；连续长段保持连续；集锦严格按分段决策输出。
- 必剪事件能够按上下半场比赛分钟校准，补时与局部素材不会错误套用整场偏移。
- 事件在素材外、未确认或与总时长冲突时，有明确可操作的提示与覆盖表。
- 多段集锦的每个切点及片头后字幕仍准确同步，并保存可追溯的原录像时间映射。
- 两三小时合成长时间轴可分块、缓存、断点恢复，不一次性加载整场音视频；不能把模拟测试写成真实直播识别验收。
- 原有 GPU/CPU、标题文件名、审批、字幕定制、片头和导出功能通过回归。

本计划尚未修改应用源代码、数据库、已有审批或视频成品。实施范围以用户后续审阅意见为准。
