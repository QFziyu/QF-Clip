# 1.8.5：统一启动与模型双模式

双击项目根目录的 `launch.cmd`，选择菜单中的一项：GPU 本地制作、CPU 本地制作、GPU 制作与发布、CPU 制作与发布。默认是 GPU 本地制作。也支持终端参数：

```powershell
.\launch.cmd --profile gpu
.\launch.cmd --profile cpu
.\launch.cmd --profile gpu --publishing
.\launch.cmd --profile cpu --publishing
```

四种选择都使用主目录的当前源码，CPU 不再指向历史源码。GPU 默认打开 8501，CPU 默认打开 8502；工作台端口被旧进程占用时自动选择后续空闲端口。自动生产服务使用固定端口，切换设备前仍需运行 `stop_automation.cmd`。启动发布服务本身不会投稿，实际发布仍需第五步确认。

本机安装了轻舟及 FootballWorkflow 时，统一入口会同时启动视频来源服务；只有选择“制作与发布”时才启动 FootballPublisher。未安装来源服务时直接启动本地工作台。CPU 优先复用版本号最新的既有 CPU 数据库；没有历史 CPU 数据时使用 `runtime-cpu`。启动器不搬移数据库、不修改已有审核。

已独立启动的轻舟可直接复用：启动器核对监听进程的绝对源码路径，并用现有配对令牌检查接口身份与版本。允许接口版本 1、主版本 1 且不低于 1.2.0 的轻舟，例如 1.2.1；Python 解释器不同或带 `-B -u --port` 不影响识别。不会关闭或接管独立轻舟。辅助服务启动失败时仍打开本地制作工作台，并明确提示视频来源／发布功能尚未就绪。

剪辑方式统一为：

- **切片**：分别输出独立短视频。
- **连续长段**：例如连续 10 分钟，段内不跳剪。
- **全场集锦**：选取多个片段拼成集锦。

“完整输出”仍可单独选择。三种剪辑形式、单路／多段顺序拼接／双路共用同一套必剪事件控件，例如 `G23:10 R40 / G61 V90+3:20`。切换剪辑形式保留事件文字；上下半场、补时及事件前后保留时长的规则一致。

在“设置 → 模型与 API”选择 **配置文件 API** 或 **官方登录（Codex / ChatGPT）**，点击“保存并使用此来源”。API 使用原有配置，并可在网页覆盖地址、密钥、模型；官方模式使用 Codex CLI 管理的登录。两套配置分别保存到 `.env.llm`，不会覆盖 `.env`。切回 API 后原有密钥仍保留。新任务读取新配置，正在运行的任务按原配置完成。

官方模式优先使用显式登录目录或当前 `CODEX_HOME`；均未指定且默认 `.codex` 没有登录文件时，检测已登录的 `.codex-official`。项目不读取或复制登录令牌，不向官方 CLI 传递项目 API Key。“检查 Codex 登录状态”只检查登录；“测试已保存配置”会实际调用一次模型。

登录机制参考 [官方 OpenAI 文档](https://learn.chatgpt.com/docs/auth)。账户额度与模型权限以实际调用结果为准。

任务记录 → 任务队列：每条等待中或执行中的任务右侧提供“取消”。等待中的任务立即取消；执行中的任务显示“正在取消”，后台终止该任务及其 FFmpeg／Codex 等子进程，然后继续其他排队任务。取消结果持久保存，重启后不会自动重新执行；需要时可在详情中点“重新执行此任务”。已完成的文件、缓存及人工审核保留。已经发到远端的模型请求可能仍消耗额度。

## 当前任务的超预算审批

字幕、剪辑方案或其他模型任务因金额预算上限拦截时，当前工作台报错处与“任务记录 → 任务队列”中都会提供预算审批入口。点击打开窗口，查看项目已计金额、默认上限、本次请求预留和预计累计金额，再选择“批准这一次并继续”或“暂不批准”。现有工程直接恢复，不用重新选择素材。

批准仅允许当前任务的一次超预算模型请求，绑定预算账本、请求和当前预留序号；批准与消耗记录持久保存，并发执行也不能重复消费。项目默认上限及历史记账保持不变。后续请求、格式降级或网络重试再次超限时仍需批准；最大调用次数限制继续生效。失败请求可能仍消耗额度。窗口金额为按项目单价估算的预留，并非服务商扣费凭据。

旧版已经失败的预算任务会根据本工程关联项目和原错误金额恢复审批入口，预留包含四位小数舍入余量。无法唯一确认账本时不会猜测批准目标，可先重试生成完整预算申请。批准后的任务继续使用已完成转录、字幕和选片窗口缓存；字幕校对会重试原先因预算失败的块。

若失败后已切换模型来源，窗口显示原预算记录并提供“按当前配置继续任务”，不会批准已经停用的 API 来源；新的请求按当前配置执行，仍复用当前工程与缓存。
