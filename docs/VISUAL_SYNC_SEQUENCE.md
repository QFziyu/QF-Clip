# 画面事件对轴与主播多素材拼接（1.4.0）

## 原来的自动对轴究竟做什么

默认方法不是让大模型听完整场比赛。程序先把所选音轨变成单声道 16 kHz 音频，每 0.5 秒提取 32 个频段的声音变化，通过 FFT 相关扫描两路的时间差，再在分散的三个位置按 0.05 秒间隔复核。共同的现场声、音乐、同一解说等可以形成指纹；不同解说、静音、重复音乐和录制中断会降低可靠性。置信度取决于匹配强度、第二候选差距和多个复核点是否一致。

勾选语义辅助后，低置信度时才会转录两路语音、从各时间段提取有限摘录，让 LLM 关联已有摘录 ID，由实际摘录时间算出偏移。它能寻找同一具体事件，但主播反应延迟、泛泛描述、回放等会造成误差，因此仅供粗定位。

偏移定义始终是：**主播录像时间 = 比赛录像时间 + 偏移**。比如同一个开球在比赛录像 100 秒、主播录像 340 秒，偏移为 +240 秒。

## 新增：开球、进球等画面事件辅助

进入「双路合成」，选择项目，展开「开球 / 进球等画面事件辅助对轴」。

1. 选择事件类型：开球、进球、红牌或自定义；可以写球队、半场、比分等补充信息。
2. 填两路中该事件出现的大概录像范围，单位为各文件从开头算起的秒数，**不是比赛时钟**。每路最大 10 分钟。例如比赛 120～180 秒，主播 360～420 秒。
3. 点击「生成事件画面对照图（不调用 API）」：后台按真实视频时间抽帧，生成带 M/C 帧 ID 和时间的对照图。每路默认 20 帧，可选 8～32 帧。完成后点「刷新画面结果」。
4. 免费手动校准：在「查看抽帧对照与手动选择同一画面」中，分别选择同一瞬间的两帧，点击「使用这两个画面位置计算偏移」。也可直接填写原有两个事件位置进行校准。
5. 可选点击「AI 匹配事件画面」：发送这些抽帧对照图到 `.env` 中配置的 OpenAI 兼容模型，需要模型支持 `image_url` 图片输入。模型只能返回现有帧 ID 和证据，程序验证后用帧时间计算偏移，不接受模型编造的时间。
6. 有建议时点击「采用画面建议偏移（仍需预览）」，生成短预览，在「同步偏移」中精调、保存。检查前后段及拼接接缝后，再勾选同步确认并导出。

画面辅助**需要两路都包含可比对的比赛画面**。主播端只有人脸时，可用原有声音匹配、语义辅助或手动定位，不能从人脸证明现场进球的准确时刻。AI 会参考球员位置、球、比分、比赛时钟和前后帧；重复开球、回放、不同机位仍可能误配。所有画面建议均显示低置信度并需要确认；多个证据偏移冲突时不给出统一偏移。抽帧误差按搜索范围、数量与源帧率估计，**不是模型识别准确率或同步精度保证**。先用大范围粗定位，再用较窄范围精调。

此版不自动扫描几小时全片识别全部进球，不自动 OCR 完整比赛时钟，不做跨录制缺口的变速或多段时钟修复。画面模型不支持图片、超时或预算不足时，保留抽帧、声音结果及手动设置；错误会显示出来，重试复用已完成缓存。只有用户明确点击 AI 按钮才发送图片，免费对照图不调用 API。

画面 API 使用独立合成项目账本 `cache/composites/ID/visual_api_ledger.json`，沿用配置的调用次数、预算、超时与有限重试；同一素材、范围、模型及接口的有效结果会复用。图片请求按请求体字节做保守预算预留，因此可能比供应商实际图像计费更早触达预算。

## 新增：主播 1 → 主播 2 首尾拼接

1. 新建双路合成，选择比赛录像，勾选「主播端有多个素材：按列表顺序首尾拼接」。
2. 点击「选择多个主播素材」打开本机文件窗口。**以上下列表显示的顺序为准**，用 ↑ / ↓ 调整，或移除多余素材。还可将上方手填路径加入列表。不会按文件名偷偷重排。
3. 指定音轨（同一音轨序号应用于每段），点击创建。后台依次标准化素材、首尾连接，关闭网页不影响任务。完成后刷新项目列表，选择新项目。
4. 此后主播时间按拼接后的总时间计算。展开「主播素材拼接顺序与时间映射」查看每段边界，再用声音或画面对轴。

支持 1～50 个不同本地素材。宽高以第一段的比例为准，工作副本最高 1920×1080，帧率使用渲染配置，画面等比缩放补边；不同编码/帧率/分辨率可以连接。没有音轨的段补静音。音频中间件使用 PCM，避免每段 AAC 编码延迟累积。按帧取整时可能在段尾复制不到一帧的画面，并保留该补齐量的映射。

标准化与拼接均在缓存中生成工作文件，不改写原素材。逐段处理控制内存，NVENC 不可用时回退 libx264；中途失败可重用已完成段。工作文件会占用额外磁盘空间，长录像可能需要数 GB。缓存与导出均记录源签名，导出时间轴能追溯到原始各段。原素材或拼接工作文件改变后要求重新建项目，避免错误复用。

**此功能是直接首尾相接，不会自动补齐真实世界的漏录时间，也不自动删除相邻文件重录的重叠内容。** 如果主播 1 和 2 之间漏了 3 分钟，一个固定偏移无法同时对齐两段；应分别建立合成项目校准。无论置信度多高，均需检查接缝前后。

## CLI

```powershell
python main.py compose-create "D:/比赛.mp4" "D:/主播1.mp4" --append-commentator "D:/主播2.mp4" --background
python main.py composites
python main.py compose-sync --composite ID --background
python main.py compose-visual-sync --composite ID --search visual_search.json --frames-only --background
# 去掉 --frames-only 即允许调用已配置的看图模型
python main.py compose-visual-sync --composite ID --search visual_search.json --background
python main.py jobs
```

`--append-commentator` 可重复指定，按参数顺序追加。GUI 和 CLI 使用同一后台流水线。`visual_search.json` 示例：

```json
{
  "event": "goal",
  "description": "下半场第一次进球，排除回放",
  "match_start": 120,
  "match_end": 180,
  "commentator_start": 360,
  "commentator_end": 420,
  "samples": 20
}
```

## 验证方式

`python scripts/run_tests.py` 运行单元、媒体及 Streamlit AppTest。

`python scripts/sequence_visual_demo.py` 使用独立的生成素材与数据库，实际执行 CLI、后台拼接、声音对轴、画面对照图和跨接缝成品导出，全程不调用 API。报告在 `output/sequence_visual_upgrade/demo/acceptance.json`。生成的彩条图不是足球事件样本，不代表真实进球识别效果；看图协议使用模拟 API 响应验证，真实比赛及实际视觉模型效果仍需实测。
